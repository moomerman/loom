# Getting started

How to start a new Loom app, for a person or an agent. You need Go 1.25
or later.

## Install and create

```
go install github.com/moomerman/loom/cmd/loom@latest
loom new myapp
cd myapp
loom dev ./cmd/myapp
```

Open http://localhost:4000: a counter whose buttons change the number
over a live connection. Edit `counter.hx` and the page reloads.

`loom new DIR` makes `DIR`, which must not exist or be empty. The module
path is `DIR`'s name; give another with `--module example.com/myapp`.
`go.mod` requires the version of Loom that `loom` was installed at, then
`loom new` runs `go mod tidy`. A `loom` built from source may have no
usable version (under `go run`, or with local changes): pass
`--loom PATH/TO/loom` to use that checkout through a `replace` line, or
run `go get github.com/moomerman/loom@main` in the app afterwards.

The app needs no database. Set `DATABASE_URL` to a Postgres database
when it needs one (`data.md`).

## The files

```
go.mod, go.sum
cmd/myapp/main.go    starts the app: loom.New, Setup, app.Run; `myapp migrate` migrates
app.go               Setup: the routes; the migrations, embedded
migrations/          SQL migrations, starting with Loom's own tables (data.md)
counter.go           a live page: its state, Mount, Assigns, Events (live.md)
counter.hx           the template it renders (syntax.md)
counter_hx.go        generated by loom build; commit it, never edit it
counter_test.go      a loomtest test of the page
layouts.hx           the root layout, the HTML document (layouts.md)
tokens.toml          design tokens for styles (components.md)
Dockerfile           a production image (deploy.md)
.gitignore, .dockerignore
```

## The agent files

Loom is new, so agents have no training data for it. `loom new` writes
what an agent needs to work on the app without this repository:

- `AGENTS.md`: what Loom is, the commands, where things live, and the
  rule to run `loom check` or `loom build` before `go test` (a stale
  `*_hx.go` still compiles).
- `CLAUDE.md`: `@AGENTS.md`, so Claude Code reads it.
- `.mcp.json`: registers `loom mcp`, which gives agents `check`, `docs`,
  `routes`, `inspect_session`, `render_component`, `recent_errors`,
  `db_schema` and the other tools (`cli.md`).
- `.claude/skills/loom/SKILL.md`: a Claude Code skill with the loop
  below and the MCP tools to use at each step.

## The loop

1. Edit a `.hx` template or its Go file.
2. `loom check`: fix each error as its fix says (`errors.md`).
3. `loom build`: regenerate `*_hx.go`.
4. `loom test`: check, build, then `go test ./...`.
5. With `loom dev` running: `loom status --wait` says whether the save
   rebuilt; look at the page, or drive it with `loom event SID EVENT`;
   then `loom errors` (server and browser), `loom sessions` and
   `loom inspect SID`. The MCP tools do the same (`dev_status`,
   `send_event`, `recent_errors`).

## Next

`loom docs` lists Loom's docs in reading order and `loom docs TOPIC`
prints one, so they're at hand outside this repository. Read `syntax`
and `live` next, then `layouts`, `components` (tokens, styles and the
starter kit: `loom components add button`), `data` and `jobs`
as you need them. `example-jobsweb` walks through a complete app.
